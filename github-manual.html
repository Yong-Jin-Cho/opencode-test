계정 연결 1번, 프로젝트 연결은 폴더마다 — 층층 구조로 이해하기

1. 깃허브란?

git은 내 컴퓨터에서 변경 이력을 저장하는 도구, GitHub는 그 이력을 인터넷에 백업·공유하는 사이트입니다.

  • git = 일기장 (매일 기록)
  • GitHub = 금고 (일기장 복사본을 안전하게 보관)

없어도 로컬 창작은 가능. 작품이 아까워지는 순간 백업용으로 연결하면 됩니다.

2. 계정 단위 vs 프로젝트 단위 — 답: 둘 다, 층이 다름

구분언제무엇을예시
계정 단위 (1회/PC)PC당 한 번github.com 로그인 인증 저장gh auth login
프로젝트 단위 (폴더마다)작품 폴더마다이 폴더 ↔ 깃허브 저장소 연결git remote add origin …

정리: 인증은 계정 단위로 1번, 연결은 프로젝트(폴더)마다 매번. 계정 1개로 프로젝트 100개를 관리하는 구조입니다.

3. 추천 사용법 — 3단계

지금

Stage 1 — 연결 없이 로컬 창작

opencode + omc 학습과 첫 작품 만들기에 집중. 깃허브·gh CLI 설치 불필요.

작품 생기면

Stage 2 — 백업 연결 (10분)

cd "작품 폴더"
git init
git add .
git commit -m "첫 저장"
gh repo create 내작품 --private --source=. --push

gh가 없으면 github.com에서 저장소를 만들고 아래 2줄로 연결:

git remote add origin https://github.com/내아이디/내작품.git
git push -u origin main

익숙해지면

Stage 3 — 자동화 (opencode github 에이전트)

  • gh CLI 설치 (https://cli.github.com)
  • opencode에서 github 에이전트로 PR 생성·리뷰 자동화
  • 프로젝트마다 remote만 걸면 같은 계정으로 계속 재사용

4. 주의사항

경고: .env (API 키)는 절대 푸시 금지. 이 폴더는 이미 .gitignore에 등록되어 있어 git add . 해도 제외됩니다. 삭제하지 마세요.
  • 저장소 공개 범위: 연습·개인 작품은 Private 선택. 남에게 보여줄 때만 Public.
  • 토큰 권한: gh auth login 시 repo 권한만 허용. 관리자 권한은 불필요.
  • 폴더당 1개: 한 폴더에 저장소 2개를 연결하지 마세요. 헷갈리면 git remote -v로 확인.
