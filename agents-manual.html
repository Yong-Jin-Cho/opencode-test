1인 개발자를 위한 init-deep / AGENTS.md 안내서

처음 접하시는 분도 순서대로 따라오시면 이해하실 수 있습니다.

1장. AGENTS.md가 뭔가요

AGENTS.md는 프로젝트의 약속을 적어 두는 설명서입니다. AI 조수(opencode 등)와 함께 일할 때, 매번 같은 설명을 반복하지 않도록 규칙을 미리 정리해 둡니다.

비유 1. 냉장고 메모

가족에게 “우유는 유통기한 확인하고, 반찬은 두 번째 칸에”라고 냉장고에 메모를 붙여 두면 매번 말하지 않아도 됩니다. AGENTS.md가 바로 그 메모입니다. AI에게 “존댓말로 짧게 답해주세요”, “테스트 후 저장해주세요” 같은 약속을 적어 둡니다.

1인 개발자에게 왜 필요합니까

1인 개발은 설계자이자 작업자이므로 기억할 일이 많습니다. AGENTS.md에 규칙을 적어 두시면 다음과 같은 도움이 됩니다.

기억 부담 감소

명령어, 폴더 규칙, 말투 규칙을 파일이 기억합니다.

일관된 결과

오늘이나 한 달 뒤나 같은 기준으로 작업합니다.

요청자님의 agent.md에 “존댓말·짧게” 규칙이 있듯이, 프로젝트별 규칙을 AGENTS.md에 옮기시면 됩니다.

2장. init-deep이 뭘 하나요

init-deep은 프로젝트를 계층적으로 살펴보고 AGENTS.md를 자동으로 작성해 주는 기능입니다. 사람이 일일이 정리하지 않아도 됩니다.

비유 2. 내비게이션 지도 만들기

처음 가는 동네에서는 큰 지도부터 보고, 다음에 골목으로 들어갑니다. init-deep도 루트 폴더부터 큰 구조를 파악한 뒤, 각 하위 모듈로 내려가며 세부 규칙을 기록합니다.

계층형 탐색에서 기록까지의 원리

1단계. 넓게 탐색 — 루트 구조, 설정 파일, 실행 명령을 확인합니다.

2단계. 깊게 탐색 — 각 모듈 폴더의 역할과 진입점을 확인합니다.

3단계. 기록 — 루트 AGENTS.md에 전체 약속을, 모듈 AGENTS.md에 세부 약속을 나누어 저장합니다.

결과적으로 “전체 지도 1장 + 골목 지도 여러 장”이 완성됩니다.

3장. 언제 실행하나요

새 프로젝트를 시작했거나, 기존 프로젝트에 설명서가 없을 때 실행하시면 됩니다.

실행 명령

/init-deep

opencode 입력창에 위 명령을 그대로 입력하시면 됩니다.

권장 시점 3가지

1. 프로젝트를 처음 받았을 때

구조 파악과 문서화를 한 번에 마치실 수 있습니다.

2. 폴더 구조가 크게 바뀌었을 때

이사 후 주소를 새로 등록하듯이 문서를 갱신합니다.

3. AI의 답변이 자주 어긋날 때

규칙이 없거나 오래된 신호이므로 다시 생성하시는 것이 좋습니다.

4장. 생성된 파일 구조 읽기

생성이 끝나면 루트에 1개, 각 모듈에 1개씩 AGENTS.md가 만들어집니다.

my-project/
  AGENTS.md            # 전체 약속 (실행법, 공통 규칙)
  src/
    AGENTS.md          # src 폴더의 약속
  tasks/
    AGENTS.md          # tasks 폴더의 약속

루트 AGENTS.md 예시

# AGENTS.md (루트)
- 프로젝트: 가정용 할 일 관리 도구
- 실행: run-opencode.bat 실행 후 opencode 시작
- 말투: 존댓말로 짧게 답변합니다.
- 작업 원칙: 수정 전 관련 파일 2개 이상 확인합니다.

모듈 AGENTS.md 예시

# tasks/AGENTS.md
- 역할: 반복 작업 스크립트 보관
- 규칙: 새 스크립트 추가 시 tasks/ 목록에 한 줄 설명을 남깁니다.
- 주의: 개인 키(.env)는 절대 포함하지 않습니다.

읽는 요령은 “루트는 전체 약속, 모듈은 그 방의 약속”으로 구분하시면 됩니다.

5장. 실제 사용 예

아래 버튼을 눌러 규칙이 없을 때와 있을 때의 차이를 비교해 보십시오.

규칙 없을 때 
사용자: 메모 저장 기능 추가해주세요.
AI: (긴 반말 + 임의 폴더에 저장)
"됐어. files/에 넣었어. 테스트는 안 했어."

매번 말투, 위치, 테스트 여부를 다시 설명해야 합니다.

규칙 있을 때 
사용자: 메모 저장 기능 추가해주세요.
AI: "tasks/에 저장 후 테스트를 마쳤습니다.
추가 확인이 필요하시면 말씀해 주십시오."

AGENTS.md의 약속(존댓말·짧게, 저장 위치, 테스트)을 그대로 따릅니다.

6장. 유지보수 방법

문서는 한 번 만들고 끝이 아니라, 바뀔 때마다 가볍게 고치는 것이 핵심입니다.

언제 업데이트합니까

실행 명령이 바뀌었을 때, 폴더가 생기거나 사라졌을 때, AI가 자주 실수할 때 업데이트하시면 됩니다.

3가지 팁

팁 1. 짧게 적습니다

긴 설명보다 한 줄 규칙 5개가 잘 지켜집니다.

팁 2. 바뀐 것만 고칩니다

전체 재생성보다 해당 모듈 파일만 수정하시면 됩니다.

팁 3. 검증 후 확정합니다

수정 뒤 간단한 작업을 시켜 규칙대로 동작하는지 확인합니다.
